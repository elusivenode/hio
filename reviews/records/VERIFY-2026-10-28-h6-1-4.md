## New finding: a trailer-free existing import can publish an unsupported index

### F-VERIFY-2026-10-28-h6-1-4-1 — high, open

`step_verify_existing_index` (`tools/hio_receive.py`) checks only the Boolean result of whether the import changed `reviews/README.md` when no `Index-Diff` trailer is present. If both the import and reviewer branch changed that path, it says the reviewer's diff was imported without comparing their content, running `check_index`, or requiring the expected import trailers. `step_merge_and_push` then accepts an ahead local `main` whose changed paths are under `reviews/`.

I built a disposable local `World(kind="verify")` fixture using the repository's real scope and assignment check tools and its small `check_repo.py` stub. The reviewer's README diff changes an existing finding from `remediation_claimed` to `verified_closed`, which option B refuses. In the scratch receiver clone, I instead checked out the exact reviewer record and handoff blobs, changed that existing finding's state in the local README, and committed it with matching `Review-Commit: <T>` and `Review-Id: VERIFY-T-2` lines but **no** `Index-Diff` trailer. This is an inconsistent pre-existing local import, not an import created by the receiver's normal path. The `--publish --without-index` restart exited **0**, printed `STATUS: received` without `PARTIAL`, and advanced disposable remote `main` with the false `verified_closed` row. The record blobs matched T, so the existing blob check did not stop it. Repeating the probe with an invented refusal trailer stopped before `main` advanced; a trailer plus a README change also stopped. The gap is specific to the no-trailer branch. The test script was run inline; no probe file was added to the repository.

The receiver's restart check must compare the existing import's README content with the result of applying and validating T's diff against the import's first parent, and reject an import that cannot be reconciled with the immutable reviewer evidence and expected receipt metadata. A changed-path Boolean cannot establish that identity. Add an adverse restart test that supplies a different README with the same changed-path Boolean and confirms remote `main` does not advance. This is a consistency stop in the assigned scope; it is distinct from the normal lost-disclosure case closed above.
