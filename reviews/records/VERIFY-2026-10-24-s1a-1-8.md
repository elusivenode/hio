## Material defect: a quarantine marker bypasses Q-002 evidence verification

At `src/hio/marketdata/vintages.py`, `_check_processed` immediately continues when
`catalogue/quarantine/receipts/<receipt_id>.json` exists. It does so before
`receipt_bytes` verifies the raw bytes and before it checks why the receipt was
quarantined. `_processing_of` likewise trusts the marker when computing the
`evidence_digest`. Approved Q-002 OBS-INV-018 requires refusal for a missing or altered
pinned receipt; OBS-INV-019 permits quarantine only when a receipt was actually
quarantined at ingest.

Two independent disposable-store reproductions use source `synthetic.daily_source`,
series `synthetic.rate`, and `as_known_by_market(T=2026-01-15T00:00Z,
Q=2026-01-15T00:00Z)`:

1. **Missing raw bytes after real quarantine.** Capture the malformed bytes
   `not a receipt\n` at `2026-01-13T12:00Z`; ingest in `SCHEDULED` mode correctly
   creates a receipt quarantine record. The query serves an empty result with
   `evidence_digest=c52c9758fe6044f667b9ff54dcd52458d1b12295a7df212d955209bab02fbf0e`.
   Delete that receipt's raw object using its normal `receipt_key`, reopen the store,
   and repeat the same query. It **still serves** the empty result with the **same
   digest**, even though the pinned raw receipt is missing. Neither query nor
   `conflicts(series_id,Q)` can prove E(Q) from that store.
2. **Forged quarantine of a valid, unprocessed receipt.** Capture a valid synthetic
   `3.60` row at `2026-01-12T01:00Z`, leave it unprocessed, then use the store's
   public `put` to create
   `catalogue/quarantine/receipts/<receipt_id>.json` with
   `{"receipt_id":"<receipt_id>","reason":"malformed"}`. Reopen and query at
   `T=Q=2026-01-13T00:00Z`. It **serves an empty result** rather than refusing
   incomplete processing, with
   `evidence_digest=f154a16d293a13c64d207e199d0036e42d6a6058b590aa9e03af653ce0f980a7`.
   The raw bytes are valid and would create a vintage if honestly ingested.

These are one defect in the quarantine bypass. The first is an ordinary integrity
failure after a genuine quarantine; the second shows why a marker's existence alone
cannot prove processing. **Smallest correction:** before accepting a quarantined
receipt for completeness or a pin, verify its captured raw bytes and capture record,
then verify the quarantine disposition against the same ingest validation that would
have quarantined it. Missing, altered or valid-but-falsely-quarantined evidence must
refuse query and resolution. Keep quarantine distinct from a quality-quarantined
vintage. Add both fixtures, including reopen and unchanged-store checks on refusal.
This is within the approved Q-002 F7 contract; it needs no new temporal or policy rule.
