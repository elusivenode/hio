## Findings

### F-REVIEW-2026-11-22-t0023-1-1 — medium, open: C5 can pass after a fiscal year is omitted

The C5 preregistration requires the fiscal years covering calendar 2008 for **each** fund, and the evidence claims six checked fund-years. `tools/t0023_sleeves.py:372-399` selects only rows present in `audited-facts.csv`; it raises when there are zero, but returns `pass` when the one supplied row passes, even if the other intended year is absent. `tests/test_t0023_sleeves.py:309-321` explicitly expects a pass with one SPY year. For example, omitting a failing 2009 row would make a passing 2008 row yield C5 `pass` rather than “not performed” for the incomplete two-year check. The actual private file was excluded, so this is a failure-mode finding, not an assertion that a row was omitted in the reported run. Pin and require the six named fund/year/accession combinations, reject missing or duplicate coverage, and test omission of each year.

### F-REVIEW-2026-11-22-t0023-1-2 — medium, open: downstream tools do not validate the frozen panel identity

`tools/t0023_common.py:49-60` chooses the newest run whose `run.json` **claims** the frozen `panel_id` and checks `panel.csv` only against the SHA in that same JSON. It never recomputes `e0003_panel.panel_id(record["inputs"], panel_sha256)` or checks the rebuild's recorded pass flags. Thus a changed panel CSV plus a corresponding changed `panel_sha256` in `run.json` is accepted under the unchanged claimed ID, and C1–C5, M1–R3, S1–S9 and the episode decision can all run on it. `tests/test_t0023_common.py:80-88` even accepts two different panel texts with the same ID and selects the newer one; the tamper test changes only the CSV, so it misses the paired change. Recompute and enforce the ID and required rebuild checks when loading, or pin a separately trusted panel SHA, and test paired CSV/record changes. The seam summary's mislabeled `panel_id` at `tools/t0023_seam.py:386` should also be corrected so it reports the actual ID.
