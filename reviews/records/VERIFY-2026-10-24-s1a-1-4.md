## F6 outcome: remediation rejected

**A concurrent reader can return an uncommitted object under the stated single-writer model.**
`get(key)` checks `_unresolved()` and then separately opens the path. Those actions have no
shared publication lock or post-read check. I forced this interleaving in a disposable store:

1. Open separate `LocalObjectStore` instances at the same root: one reader, one writer.
   Pre-create `catalogue/`, so the writer's staged `catalogue/b=b'b'` takes the journalled path.
2. Start the reader's `get('catalogue/b')`. Pause it immediately after its `_unresolved()`
   check returns the empty set, before `get` opens the path.
3. Start the sole writer's `StagedWrites.commit()`. Pause `os.chmod(catalogue/b)` after
   `os.link` has made `b` visible but before the journal is removed. Confirm that the journal
   still exists.
4. Resume the reader while the writer remains paused. `get` returns **`b'b'`** even though
   the transaction is unresolved. Only then resume the writer.

The probe used two threads, **one writer and one reader**. It made no implementation edits.
The claimed boundary is that uncommitted objects are not observable through the supported
interface while their transaction remains unresolved, including from a store already open.
The reader observed one. The same check-then-access pattern warrants scrutiny in `exists`,
`list` and `snapshot`; this record directly demonstrates `get`.

The minimum closure is an adversarial interleaving test in which a reader starts before the
journal is created, the writer links an object and remains unresolved, and the reader cannot
return its bytes or list it. Preserve the previous short-write, torn-journal, failed-rollback,
ownership, crash and successful-commit guarantees. A code change must provide a clear
publication point for supported reads across open store instances. If that requires changing
the approved storage contract or a general concurrency design beyond OD-0025, stop and put a
small decision request to the owner and solution architect rather than weakening the test.

F6 remains open. F1, F2, F3 and F5 remain verified closed at the prior head with no
implementation change in this range and passing regression tests. F4 and F7 remain open
policy questions. No finding is waived; S1a is not accepted and S1b is not authorised.
