## Findings

### F-REVIEW-2026-11-04-t0022-1-1 — Q1 passes without checking the quote currency (high, open)

E-0002 pre-registration `registers/experiments.yaml:67` requires USD quote currency for SPY, IEF and BIL. `tools/eodhd_eval.py:288-295` sets Q1 from rows, dates, closes and gaps alone. The only currency comparison, at lines 318-321, concerns *distribution* currency for Q2. An invented EOD series explicitly marked EUR with no distributions passed Q1, Q2 and Q3. The three-sleeve comparison gate at lines 638-649 can therefore run on a misdenominated sleeve. The assessment's Q1-to-Q3 pass is narrower than its pre-registered meaning. Verify quote currency from an appropriate source, or fail Q1 when it is unknown; add an invented wrong/unknown-currency refusal case.

### F-REVIEW-2026-11-04-t0022-1-2 — Q3 silently drops missing adjusted-close periods (high, open)

E-0002 pre-registration `registers/experiments.yaml:69` requires agreement in at least 99% of periods. `tools/eodhd_eval.py:351-375` computes that fraction only over periods whose two adjusted closes are present; `missing_adjusted` is counted but does not affect Q3. My four-date invented probe had three total periods, two missing adjusted comparisons, and one agreeing comparison; Q3 passed and can open the portfolio gate. A single agreeing pair could thus qualify an arbitrarily long, mostly unassessable sleeve. Require adjusted-close coverage for the pre-registered denominator or explicitly record an owner-approved variant; add a missing-adjusted refusal case.

### F-REVIEW-2026-11-04-t0022-1-3 — A snapshot name can move licensed raw bytes outside the workspace (high, open)

The task card `registers/tasks/T-0022-eodhd-evaluation.md:26-28` requires a segregated workspace outside the repository. `tools/eodhd_eval.py:171-190` checks only `root.resolve()`, then appends the unvalidated `snapshot` string. `pathlib` discards preceding components for an absolute snapshot; `..` can likewise escape. A new target within the repository can therefore be created and filled with response bytes at lines 190-227 while `check_root(root)` has passed. This is a path-boundary failure in the fetch operation; it does not require a live credential to reproduce. Restrict snapshot to a safe single component and verify the resolved target stays under the intended raw directory before any fetch or write.

### F-REVIEW-2026-11-04-t0022-1-4 — The private-workspace mode is not enforced (high, open)

The same task-card paragraph requires mode 700. `tools/eodhd_eval.py:190,206,227,677-682` creates directories and writes raw and derived files using ambient process defaults, with no mode check or restrictive creation mode. `check_root` enforces only repository exclusion. With a permissive pre-existing root or ordinary umask, licensed bytes and owner-only results can be readable by other local users. Refuse an unsafe root and create private subdirectories and files, including the reports and store, under a restrictive mode; test the refusal and resulting modes on invented data.

### F-REVIEW-2026-11-04-t0022-1-5 — The assessment includes a licensed-derived magnitude claim in agent-visible text (high, open)

`registers/sources.yaml` sets `quotation_in_documents: deny` and `agent_context: deny` for this evaluation. `docs/evidence/e0002/assessment-1.md:12` says no value is recorded there; line 44 nevertheless states both the direction and a numerical magnitude bound for a vendor-versus-issuer distribution discrepancy, and interprets the vendor's adjusted close against that issuer amount. That bound is calculated from licensed observations, even though the underlying amounts are withheld. Remove the magnitude bound and retain the discrepancy as a count/status claim; keep the detailed comparison only in the local owner report while these permissions deny agent use and quotation. This record deliberately does not repeat the bound or any licensed value.
