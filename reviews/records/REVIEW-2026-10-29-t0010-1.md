## Findings

### F-REVIEW-2026-10-29-t0010-1-1 — high, open: cross-origin redirects bypass the approved request identity

`HttpTransport.get` in `src/hio/sources/http_transport.py:65-74` follows a `Location` with `urljoin` and makes the next request after checking only its scheme and generic URL shape (`:90-125`). `run_capture` in `src/hio/sources/run.py:49-58` checks rights for the original publication's datasets before the call, without a check of the next origin or final URL. A two-server local probe showed that a 302 from the first server causes a GET to a different loopback port and returns that server's body. The production code permits the same move between HTTPS origins. An approved publisher URL can therefore redirect HIO to request and retain an unapproved third-party response as if it were the approved dataset. This breaks T-0010 W-1's adapter boundary, the approved request identity in T-0009, and the rule that unknown source rights deny use. Refuse a cross-origin redirect unless its target is explicitly approved for that dataset and request; add a local two-origin negative test. No public data source was contacted for this finding.

### F-REVIEW-2026-10-29-t0010-1-2 — high, open: a run from another GitHub workflow can become finality evidence

HIO-ADR-0012 §4.3.3 requires a run outside the scheduled or dispatched capture workflow on `main` to record `platform: other`; its trusted-adapter assumption is that workflow on `main`. `Execution.from_environ` (`src/hio/marketdata/runrecord.py:45-55`) marks **every** GitHub Actions run as `github_actions`, regardless of `GITHUB_WORKFLOW`, `GITHUB_REF` or event. C6 (`src/hio/marketdata/finality.py:377-400`) checks only platform, pinned SHA, numeric run id and attempt, and a nonempty job. A synthetic attempt whose job was `unrelated_ci_job`, with otherwise valid retained bytes and times, passed C1–C7 and made `vintage_finality(...).final` true. A run on another workflow at the same commit can thus be accepted as the CI witness required for finality. Bind the producer to the capture workflow, `main` and allowed triggers, and make C6 reject an unrelated job or otherwise verify that provenance before any final verdict; add a negative test for a different workflow and ref. The later sample CI-history audit does not repair a false final verdict at build time.
