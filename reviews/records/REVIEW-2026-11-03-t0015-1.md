## Finding

### F-REVIEW-2026-11-03-t0015-1-1 — medium, open: an inconclusive properties result is treated as proof of existence

`src/hio/storage/azure_blob.py:175-182` discards the return value of `get_blob_properties()` and returns `True` whenever that call does not raise. With an absent key, a conditional upload fake returning the original 403 `UnauthorizedBlobOverwrite`, and a properties fake returning `None`, `create()` raises `BlobExists` instead of the original 403. I reproduced this with the existing fake container and a one-call override of `FakeBlobClient.get_blob_properties`. The F-1 acceptance criterion expressly requires an inconclusive existence check to preserve the original error. Require a substantive properties result for the exact key; an absent or malformed result must leave the original 403 intact. Add a regression case for an inconclusive non-exception result.
