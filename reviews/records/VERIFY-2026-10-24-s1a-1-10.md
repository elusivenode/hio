## Material counterexample: invalid `recorded_at` is accepted under unchanged pins

Approved Q-001 §2 requires `decided_at` never to precede the instant the quality event
was recorded. Approved Q-002-R1 §2 excludes `recorded_at` from `quality_digest`
*because it serves that no-backdating check*. `VintageStore.set_quality` enforces the
rule on new writes, but `VintageStore._load` accepts a stored event without checking
`recorded_at` against `decided_at`. The four-pin verification likewise does not check
the event's internal clock validity.

Independent disposable-store reproduction:

1. Capture and ingest `synthetic.rate`, valid date `2026-01-12`, value `3.60`, with
   `published_at=2026-01-12T00:00Z`, captured `2026-01-12T01:00Z`, in `SCHEDULED`
   mode. Record an owner `QUARANTINED` decision for vintage 1 with
   `decided_at=2026-01-14T00:00Z`; the synthetic recording clock is
   `2026-01-01T00:00Z`, so the original event is valid. Save the view and all four
   pins at `as_captured_by_hio(T=2026-01-15T00:00Z)`.
2. In the disposable store, change only the event object's `recorded_at` to
   `2026-01-16T00:00Z`. The persisted event now claims that HIO made the decision
   **two days before it was recorded**, and it was not even recorded by the query
   cutoff. Its `status`, `decided_at`, actor, evidence and vintage identity are
   unchanged.
3. Reopen `VintageStore` and call `verify_pins` with the original view's four pins.
   It **returns the same view** and reports all four pins equal. A direct historical
   query likewise applies the impossible decision. No exception is raised.

The original event's `recorded_at` was
`2026-01-01T00:00:00.000000Z`; after alteration it is
`2026-01-16T00:00:00.000000Z`; `decided_at` remains
`2026-01-14T00:00:00.000000Z`. This is not an acceptable faithful copy under Q-001.
The author's AT-Q2R1-3 changes `recorded_at` only to another *valid* value
(`2026-01-02`) and checks digest equality, so it misses the invalid-clock case.
An exact release input carrying the original raw object reference would detect
different bytes; `verify_pins` and a newly built view do not. Q-002-R1's excluded-field
rule therefore relies on validation that the reload path does not perform.

**Smallest correction:** validate every loaded quality event's `recorded_at ≤
decided_at` and `decided_at >` its vintage's `captured_at`, using the same Q-001
decision-clock rule as `set_quality`. Reject an invalid stored event before it can
contribute to a view, digest, pin verification or release. Keep valid changes to
excluded storage fields digest-neutral. Add a regression that mutates `recorded_at`
past `decided_at`, reopens, and asserts refusal; check the before-capture clock too.
This is a technical integrity correction under the existing approved contracts.
It requires no new policy or financial rule.
